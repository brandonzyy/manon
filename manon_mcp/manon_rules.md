# Manon 调用规则

## 适用范围（MUST）

Manon 只用于**核心功能源码**的代码任务，不是普通搜索、审计或文件修改的默认前置步骤。

核心功能源码是会直接改变产品、服务、Agent、公共库或运行时行为的生产代码。只有任务需要理解这类源码的语义、架构、调用关系、依赖或改动影响时，才调用 Manon。

以下内容不调用 Manon：

- 文档、说明、注释和验收记录；
- 配置、YAML、JSON、TOML、plist 和数据库记录；
- 测试、fixture、mock、样例和快照；
- CI、部署、运维、环境、进程、网络、代理、服务和日志排障；
- 纯格式、文件定位、固定字符串搜索和简单状态检查；
- 新建独立脚本或小工具，且不需要理解既有核心源码调用关系。

如果一个任务同时涉及核心功能源码和上述非核心内容，只对核心功能源码部分使用 Manon；不要因为同一 PR 里附带了测试、文档或配置，就扩大 Manon 的调用范围。

## 核心源码中的工具选择

| 场景 | 工具 | 说明 |
|------|------|------|
| 代码搜索/理解 | `manon_search` | 语义搜索实体和关系 |
| 深度问答 | `manon_deep_query` | 多轮迭代，自动覆盖子问题 |
| 调用关系/依赖 | `manon_graph` | symbol 级图遍历（callers/callees/both） |
| 改动影响 | `manon_impact` | commit 级影响传播分析 |
| 代码健康度 | `manon_code_health` | 8 维度评分 |
| 初始化/连接 | `manon_init` | 匹配或创建仓库 + 索引 |

## 核心源码规则

### 规则 1：语义搜索与架构探索先查图谱

对核心功能源码做语义搜索、架构分析或大范围探索时，先使用 `manon_search`、`manon_deep_query` 或 `manon_graph`。图谱覆盖不足时再使用文件搜索补充，并说明“图谱未覆盖，补充搜索”。

精确查找已知文件名、固定字符串、配置值或日志内容，可以直接使用 `rg`。

### 规则 2：核心源码改动前查上下文和近史

修改核心功能源码中的公共函数、类、接口、跨模块 import，或改动会影响多个模块时：

- 先用 `manon_search` 或 `manon_graph` 了解调用与依赖上下文；
- 对已有且受 Git 管理的目标文件执行 `git log --oneline -10 -- <file>`，或使用 `manon_impact`；
- 新文件、未跟踪文件和非 Git 目录不强制执行 `git log`。

### 规则 3：按需初始化

只有任务确实涉及核心功能源码且没有可用图谱时，才调用 `manon_repos_list` / `manon_init`。不要为非核心任务创建、扫描或上传 Manon 仓库。

## 执行顺序

1. 先判断任务是否涉及核心功能源码。
2. 不涉及：直接搜索、修改与验证，不调用 Manon。
3. 涉及：只对核心源码部分先查图谱，再补充文件搜索、修改与验证。
4. 无论是否使用 Manon，都保护用户现有改动，并进行与风险相称的验证。
