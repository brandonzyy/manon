# 行为层体检 (AUDIT)

**Philosophy**：结构分回答「形状对不对」，测试回答「正路走得通」。
这两样同时为绿，仍然可以有一批缺陷活着——它们全在**负向路径**上。
这个 skill 只找那一类。

先跑确定性的对账表划定范围，再把语义审计**只投到有嫌疑的面上**。
全仓语义扫描贵且有误报，不该每次都做。

## Prerequisites
调 `mcp__manon__manon_repos_list`。失败 → 提示安装并 STOP。

---

## ⚠️ PATH RULES
```
AUDITOR = <MANON_DIR>/scripts/manon-contract-audit.py   ← 四张对账表，零模型
```

`MANON_DIR` 从 `mcp__manon__manon_init` 的输出里取（`<!-- MANON_DIR=... -->`）。

## 执行流程
### Step 1 — 对账表划范围（必做，别跳）
```bash
"<MANON_PYTHON>" "<AUDITOR>" <project_path> --json
```

拿到四张表：`endpoints` / `configs` / `states` / `envelope`。
它们是**事实**（谁定义、谁消费），不是判断。用途有两个：

1. `verdict=dead` 的条目直接进「死面清单」，不需要语义审计——去确认它是该退役还是该登记为运维口；
2. `verdict=suspect` 的条目标出**哪些面可疑**，Step 3 的语义审计优先投这些面。

### Step 2 — 定审计面

问用户或从 `git diff` 推断本轮要审的范围：

| 输入 | 审计面 |
|---|---|
| 用户给了模块/目录 | 就那块 |
| 有未合并分支 | `git diff main...HEAD --name-only` 命中的文件所属模块 |
| 都没有 | 从对账表 suspect 密度最高的 3 个模块起手 |

**不要默认全仓**。全仓语义体检是季度动作，不是日常动作。

### Step 3 — 五类谱系并行审计

五类谱系分别是什么、各自怎么审、判据与反例见
[references/五谱系.md](references/五谱系.md)。
### Step 4 — 汇总

按严重度排序输出，每条必须有：

| 字段 | 要求 |
|---|---|
| 位置 | `文件:行` |
| 缺陷 | 一句话说清楚「判据是什么、为什么在真实输入域下不成立」 |
| 影响 | 谁会受损、什么条件下触发 |
| 缺失的负向用例 | **具体到测什么输入、断言什么** —— 这是修复的完成判据 |

同根因的多处合并成一条，注明所有位置（谱系①最常见）。

**不要凑数**。每条都必须两侧代码亲读确认，grep 命中不算证据。
体检的另一半价值是「核对无恙」的部分——把主链路查干净了也要说，
否则下次没人知道哪里已经查过。

### Step 5 — 落棘轮（防再生）

修完不算完。每类缺陷发现一次，就要留下一条机器可判的规则，否则下轮原样长回来：

| 发现了什么 | 留下什么 |
|---|---|
| 谱系①②③④ 的任一条 | 它的**负向测试**，作为合并硬性要求 |
| 一类同根因出现 ≥2 处 | 一条 code review 清单项 |
| 新的死面类型 | 加进对账表的判据，或加一条门禁脚本 |
| 刻意保留的死面 | `.manon-contract.yaml` 的 exempt 条目 |

装完棘轮后重跑 Step 1，确认 `dead` 计数确实下降。

## 与其它 skill 的分工

| skill | 管什么 |
|---|---|
| `/audit` | 行为层缺陷：假成功、守卫失效、闭环无证据、契约错位、死面 |
| `/assurance` | 装保障栈；其覆盖循环管「哪些代码没测试」 |
| `/dao` | 结构：耦合、重复、过度抽象 |
| `/retire-checks` | 过期的检查器本身 |

覆盖循环加覆盖，`/audit` 找测试覆盖不到的那类缺陷——**测试全绿正是这些缺陷能活下来的原因**，
所以别指望覆盖补齐了就不用 `/audit`。
