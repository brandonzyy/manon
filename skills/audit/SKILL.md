# 行为层体检 (AUDIT)

**Philosophy**：结构分回答「形状对不对」，测试回答「正路走得通」。
这两样同时为绿，仍然可以有一批缺陷活着——它们全在**负向路径**上。
这个 skill 只找那一类。

先跑确定性的对账表划定范围，再把语义审计**只投到有嫌疑的面上**。
全仓语义扫描贵且有误报，不该每次都做。

## Prerequisites

调 `mcp__manon__manon_repos_list`。失败 → 提示安装并 STOP。

---

## ⚠️ PATH RULES

```
AUDITOR = <MANON_DIR>/scripts/manon-contract-audit.py   ← 四张对账表，零模型
```

`MANON_DIR` 从 `mcp__manon__manon_init` 的输出里取（`<!-- MANON_DIR=... -->`）。

## 执行流程

### Step 1 — 对账表划范围（必做，别跳）

```bash
"<MANON_PYTHON>" "<AUDITOR>" <project_path> --json
```

拿到四张表：`endpoints` / `configs` / `states` / `envelope`。
它们是**事实**（谁定义、谁消费），不是判断。用途有两个：

1. `verdict=dead` 的条目直接进「死面清单」，不需要语义审计——去确认它是该退役还是该登记为运维口；
2. `verdict=suspect` 的条目标出**哪些面可疑**，Step 3 的语义审计优先投这些面。

### Step 2 — 定审计面

问用户或从 `git diff` 推断本轮要审的范围：

| 输入 | 审计面 |
|---|---|
| 用户给了模块/目录 | 就那块 |
| 有未合并分支 | `git diff main...HEAD --name-only` 命中的文件所属模块 |
| 都没有 | 从对账表 suspect 密度最高的 3 个模块起手 |

**不要默认全仓**。全仓语义体检是季度动作，不是日常动作。

### Step 3 — 五类谱系并行审计

对每个审计面，按下表**并行**派子代理，一类一个。每类的判据是固定的，不要临场发挥。

#### 谱系① 假成功（成功判据 ≠ 被调方的失败约定）

**怎么读**：找所有「把状态翻成成功」的写入点——渲染 ✅ 的卡片、置 `success`、回 200、
写终局状态。对每一处，回到**被调方**看它的返回约定。

**判据**：调用方用来判成功的东西，在被调方的**全部失败路径**上是否也成立？
典型形态：`if resp:` 判成功，而被调方失败时返回的是非空的错误文案。

**同仓佐证**：同一文件里若已有按业务标志区分成败的分支，那是正确写法，
漏掉的分支就是缺陷（同根因多处并发）。

**必须产出的负向用例**：让被调方走每一条失败路径，断言状态**没有**被翻成成功。

#### 谱系② 守卫失效（判据在真实输入域下不成立）

**怎么读**：列出所有守卫——装饰器、依赖注入、`if not authorized: raise`、白名单、签名校验。
对每一个，问三件事：

1. **入口是否都经过它**？回调、webhook、卡片动作这类入口常常不走框架的那条路，
   于是全仓的 `@requires` 对它一个字都不生效。对账表的 `envelope` 表就是干这个的，先看它。
2. **异常路径 fail-open 还是 fail-closed**？`except: pass` 之后还继续执行的守卫等于没有。
3. **判据在真实输入域下成立吗**？逐字符包含 vs 子串、非常量时间比较、
   白名单只写在 docstring 里、进程内字典当幂等键（多 worker/重启即失效）。

**必须产出的负向用例**：构造恰好落在判据外的输入，断言被拒。

#### 谱系③ 状态闭环无证据（终局状态置位时没有引用证据）

**怎么读**：从对账表 `states` 里取该模块的状态值，找每个**终局态**的写入点。

**判据**：置位那一刻，代码引用了什么证据？
- 引用了外部系统的终态回执（银行回单、审批 API 实查、网关查单）→ 闭环成立
- 只引用了「我方已提交」「通知已送达」→ **闭环不成立**，这是缺陷

**配套要查**：终局态的**回退路径**存在吗？被驳回/失败时，状态退回去了吗？
若过滤条件按终局态排除记录（`WHERE status <> 'done'`），不回退就等于永久丢失。

**必须产出的负向用例**：让外部系统返回失败/驳回，断言状态没有置位，或已回退。

#### 谱系④ 契约错位（两侧对不齐）

**怎么读**：三个方向逐字段比对——
端点模型 ↔ 服务函数签名、前端请求体 ↔ 后端模型、跨进程 payload 的生产方 ↔ 消费方。

对账表的 `endpoints` 已经给了路径层的错位（前端调了不存在的端点、代理漏配）。
这一步查的是**字段层**：同名不同义、必填可选不一致、枚举值两侧不等。

**必须产出的负向用例**：用真实 payload 打一遍，断言两侧字段一致。

#### 谱系⑤ 死面确认（对账表已给出，这里只做退役决策）

对 `verdict=dead` 的每一条，二选一：

- **退役** → 删掉，同时删掉它专属的服务函数/常量（别只删壳）
- **保留** → 写进仓根 `.manon-contract.yaml` 的 `exempt`，**必须带 reason**

```yaml
exempt:
  endpoints:
    - id: "GET /admin/orgs/{org_id}/pilot-access"
      reason: "运维 curl 保留口，白名单授权走这里"
  configs:
    - id: "env:CASEOS_GIT_ROOT"
      reason: "留给 v2 的 git 后端，Q4 前不接就删"
```

第三条路（「先放着」）不存在——放着就是下轮重报，重报几次这张表就没人看了。

### Step 4 — 汇总

按严重度排序输出，每条必须有：

| 字段 | 要求 |
|---|---|
| 位置 | `文件:行` |
| 缺陷 | 一句话说清楚「判据是什么、为什么在真实输入域下不成立」 |
| 影响 | 谁会受损、什么条件下触发 |
| 缺失的负向用例 | **具体到测什么输入、断言什么** —— 这是修复的完成判据 |

同根因的多处合并成一条，注明所有位置（谱系①最常见）。

**不要凑数**。每条都必须两侧代码亲读确认，grep 命中不算证据。
体检的另一半价值是「核对无恙」的部分——把主链路查干净了也要说，
否则下次没人知道哪里已经查过。

### Step 5 — 落棘轮（防再生）

修完不算完。每类缺陷发现一次，就要留下一条机器可判的规则，否则下轮原样长回来：

| 发现了什么 | 留下什么 |
|---|---|
| 谱系①②③④ 的任一条 | 它的**负向测试**，作为合并硬性要求 |
| 一类同根因出现 ≥2 处 | 一条 code review 清单项 |
| 新的死面类型 | 加进对账表的判据，或加一条门禁脚本 |
| 刻意保留的死面 | `.manon-contract.yaml` 的 exempt 条目 |

装完棘轮后重跑 Step 1，确认 `dead` 计数确实下降。

## 与其它 skill 的分工

| skill | 管什么 |
|---|---|
| `/audit` | 行为层缺陷：假成功、守卫失效、闭环无证据、契约错位、死面 |
| `/tc` | 覆盖率：哪些代码没测试 |
| `/dao` | 结构：耦合、重复、过度抽象 |
| `/retire-checks` | 过期的检查器本身 |

`/tc` 加覆盖，`/audit` 找测试覆盖不到的那类缺陷——**测试全绿正是这些缺陷能活下来的原因**，
所以别指望 `/tc` 跑完就不用 `/audit`。
