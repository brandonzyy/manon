# /assurance — 工程保障体系的唯一入口

**判据只有一份**：[references/判据.md](references/判据.md)。本 skill 是它的执行流程，不重复它的定义。
**开工前先读它**（四层保证栈、两条元规则、缺陷沉降）。

## 触发
「跑一下 assurance / 体检 / 合规检查」「这个项目的保障体系怎么样」「按体系规范补齐」，
新项目「按 Day-0 清单装一下」，以及「简化代码 / 降复杂度」「审行为层 / 找测试抓不到的
缺陷」「门禁太多 / 这些测试还有用吗」。**体系里的活不确定该走哪条，一律从这儿进**
——Step 2 按读数分诊，不靠印象。

---

## Step 1 — 体检（必做，先别动手）
```bash
python3 <SKILL_DIR>/scripts/assurance_check.py <项目路径>
```

输出三态。**三态的读法比分数重要**：

| 状态 | 含义 | 怎么办 |
|---|---|---|
| `OK` | 配置存在**且**被至少一个执行器引用 | — |
| `CONFIGURED_NOT_RUN` | 配置在，无执行器 | **最先修这一类**。它比缺更危险——看起来像装了 |
| `MISSING` | 没有 | 按 Step 4 排期 |

两条读数纪律：

1. **CI 那一格是整张表唯一可能假绿的**。工具只能看到配置在不在，看不到平台有没有启用、
   流水线有没有跑过。看到它绿，要追一句「最近一次真跑绿是什么时候」。
2. **分数不是目标**。17/17 但没人看棘轮存量，等于没装。

## Step 2 — 分诊（读数决定走哪条）

**三态全绿不等于收工，只等于装齐了。** 体系还有四条循环，各带着自己的判据与工具——
**打开对应的 references 再动手**，不在这一页顺手做掉：

| Step 1 之后的读数 / 需求 | 走 |
|---|---|
| 有 `MISSING` / `CONFIGURED_NOT_RUN` | 留在本 skill，Step 3 起 |
| 全绿，覆盖率棘轮有零覆盖分支 / 要补测试 | [覆盖循环](references/覆盖循环.md) |
| 全绿，找测试与图谱都抓不到的行为层缺陷 | [行为层审计](references/行为层审计.md)（硬依赖 manon） |
| 降结构复杂度：耦合、重复、过度抽象、死代码 | [结构简化](references/结构简化.md)（硬依赖 manon） |
| 全绿，inventory 报重复执行／零执行／空转 | [检查退役](references/检查退役.md) |

inventory 指 `python3 <SKILL_DIR>/scripts/retire_checks.py inventory --root <目录>`；
标了「硬依赖 manon」的两条，先跑 `/manon` 激活图谱再进。

## Step 3 — 定模式

| 情况 | 走哪条 |
|---|---|
| 新仓、第一次提交之前 | **Day-0**：把 L1 五件套一次装齐。此时存量为零，成本最低 |
| 存量项目 | **补齐序列**：走 Step 4。**一阶段一个终态，绝不并行**——同时上三个工具会一次报几千条，然后就放弃了 |

## Step 4 — 补齐序列（存量项目）

每阶段的终态判据必须是**一条可跑的命令**，不是一句描述。

| 阶段 | 动作 | 为什么是这个顺序 |
|---|---|---|
| P1 白捡 | 找出所有 `CONFIGURED_NOT_RUN`，接上执行器 | 零边际成本，配置已经在了 |
| P2 死面 | 死代码工具 + 「每个脚本答得出谁执行它」的不变量 + 孤儿处置 | 先把仓库缩小，后面每一步都更便宜 |
| P3 执行器 | CI：PR 上从**干净克隆**跑一次 | 之后新装的检查自动获得非本机执行器 |
| P4 类型 | 类型检查 + baseline 棘轮 | 最大长期收益，但**必须 baseline** 才不至于放弃 |
| P5 覆盖 | 覆盖率测量 + 棘轮 + 零覆盖分支清单（[覆盖循环](references/覆盖循环.md)） | 依赖 CI 才有稳定基线 |
| P6 变异 | 核心模块跑一轮 | 最贵，放最后，一次性 |

执行前必做的三件事、棘轮为什么是默认形态、什么不能进提交钩子、**需要人拍板的四类**
—— 见 [references/补齐要点.md](references/补齐要点.md)。

## 硬规则

**不许只为把格子翻绿而丢一个配置文件进去。** 那正是 `CONFIGURED_NOT_RUN`——本体系要防的头号失效。
每装一件工具，必须同时回答「谁执行它」，并登记进那份唯一的清单。

**每一件工具都要说得出它抓的是哪一类缺陷。** 说不出的规则不选。
报了没人修的规则会让人整个不看输出，那这条门禁就白装了。存量报太多时**收窄规则集**，而不是调低门槛。

## 落账

1. **跟踪线**：存量补齐建一份计划（`docs/plans/…·执行中.md` 或等价物），每个工作项带**可跑的终态判据**。
2. **事故页**：静默失效各成一页（`docs/incidents/`），「防复发」栏除写哪个检查器守着，
   **还要回答「有没有通用工具能抓这一整类」**——有就装工具，别只写自定义检查器。
3. **回写判据**：踩到新坑就补进 [references/补齐要点.md](references/补齐要点.md)——那是给下一个执行的人的。

## 收尾

再跑一次 Step 1。**0 MISSING / 0 CONFIGURED_NOT_RUN 才算这一轮完成**，
且要在收尾时明确说出「CI 那格是不是真跑绿过」，并按 Step 2 说清分诊到了哪条、还是就此收工。

计划里还有未闭合项时，**状态后缀不许翻成「已完成」**——把「未开始」写成「已完成」是命名谎言。
