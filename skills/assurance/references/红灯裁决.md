# 红灯裁决 —— 命令失败不是红灯，只是待验证结果

**模型无权把待验证结果升级为红灯。** 一条命令退出非零只给出「当前结果」；
「当前内容有没有问题」这个判断要等这套裁决走完才算数。没走完之前，
不许拿它阻断流程，也不许拿它授权改业务代码。

## 四种权威结果

| 结果 | 含义 | 动作 |
|---|---|---|
| `PASS` | 检查通过 | 继续 |
| `RED` | 基线绿、当前稳定失败，并能建立「改动 → 失败」的因果链 | 才能阻断或改业务代码 |
| `INVALID` | 判据、范围、基线或检查器错误 | 修门禁，不改业务代码 |
| `UNKNOWN` | 环境故障、结果翻转或证据不足 | 停止，修环境或补证据 |

## 每条失败留一行回执

```text
内容标识 | 命令 | 当前结果 | 基线结果/有效回执 | 权威结果 | 证据
```

- **内容标识**：这次判的是哪份内容（commit / 文件集 / 分支），不是「第几次跑」。
- **基线结果**：优先取**已有的有效回执**；没有才补跑一次基线。
- **证据**：能让下一个人复核的东西——行号、另一端口的读数、diff、日志。

## 七条裁决规则

1. 同一内容、同一环境、同一命令**最多执行两次**。
2. 第二次仍失败而没有新增证据，**禁止继续重跑**。
3. 优先使用已有的有效基线回执；没有才补跑一次基线。
4. 基线也失败，结果只能是 `INVALID` 或 `UNKNOWN`，不能是 `RED`。
5. 相同内容结果翻转，结果只能是 `UNKNOWN`，不能是 `RED`。
6. 没有建立「改动 → 失败」的因果链，结果不能是 `RED`。
7. **只有 `RED` 能阻断流程或授权模型修改业务代码。**

## 判成 `INVALID` 的代价为什么必须写清

判据把范围划错时读数是**假红**，而假红不是「多看一眼」的量级：它会把人引向业务代码，
或者逼人为了翻绿塞一份空配置——后者正是本体系防的头号失效（`CONFIGURED_NOT_RUN` 的同族）。

判例（2026-09-11，存量仓甲）：`assurance-check.py` 旧实现只把 `scripts/` 当执行器面，
同一个仓同一天两份读数——旧入口 `OK 2 / 配了没跑 1 / 缺 11`（lint、类型、死代码、
覆盖率全报缺），新入口 `OK 8 / 配了没跑 0 / 缺 6`。而该仓 `quality/gates.sh:243/248/251`
真有 ruff / mypy / vulture 调用、`:204/233/407` 真有 coverage。
裁决 `INVALID`：判据范围错，修检查器，不碰业务代码。

## 重跑纪律

同一内容、同一环境、同一命令的第三次执行，在没有新证据时**没有信息量**：
判据没变、基线没变，它只会把同一份待验证结果再打印一遍。要重跑，先说出这一轮
**新增了什么**（换了环境？补了基线？改了判据？）——说不出来就别跑。
重复执行是删哪一处的判断，见 [检查退役.md](检查退役.md)。
