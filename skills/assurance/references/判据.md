# 判据 —— 四层保证栈 · 两条元规则 · 缺陷沉降

本 skill 的执行流程建立在这四条判据上。**若你的仓库或本机另有更细的保障体系规范，
以那一份为准**，本文件只保证 skill 自身可独立运转。

## 一、四层保证栈

四层齐备，层与层不可互相替代。**缺一层就是缺一整类缺陷的探测能力。**

| 层 | 回答 | 典型工具 | 缺了会漏掉 |
|---|---|---|---|
| **L0 结构** | 代码**长得**对不对 | manon graph / contract-audit | 死端点、死配置、没有守卫的入口 |
| **L1 机器** | 有没有**不需要人事先想到**的缺陷 | 类型 / lint / 死代码 / 覆盖率 / 变异 | 类型级 bug、未执行的分支、无断言的测试 |
| **L2 门禁** | 我**已经知道**的失效模式有没有复发 | 手写 `check_*`，一事故一门禁 | 领域特定的旧账重演 |
| **L3 行为** | 前三层全绿之后还剩什么 | 行为层审计（[五谱系](五谱系.md)）/ e2e | 假成功、守卫失效、闭环无证据、契约错位 |

**L1 是绝大多数项目缺的那一层**，也是唯一能抓「你没想到」的那一层。用「再审一遍」代替它
是徒劳的：审计的边际收益递减，第 N 轮的产出远低于装一个类型检查器。五件套语言无关：

| 件 | 抓什么 | Python | TypeScript | Go |
|---|---|---|---|---|
| lint | 未使用导入/变量、注释掉的代码 | ruff (`F`,`B`,`ARG`,`ERA`) | eslint / oxlint | `go vet` |
| 类型 | 类型级 bug，投产比最高的一件 | mypy / pyright | `tsc --strict` | 编译器自带 |
| 死代码 | 冗余设计的机器化定义 | vulture | knip | `deadcode` |
| 覆盖率 | **从未执行过的分支** | pytest-cov | vitest / c8 | `go test -cover` |
| 变异 | **测试是否真的能抓 bug** | mutmut / cosmic-ray | Stryker | 自研 |

变异测试是唯一直接回答「测试全绿但我还是不放心」的方法：把 `>` 改成 `>=`、`and` 改成 `or`，
看测试挂不挂。不挂＝那行代码没有任何测试在保护它。**不必全仓跑**，核心模块一年一次即可。

L0 的终态是四张对账表干净、或每条豁免带**可核对的** reason。L2 的每一条必须追溯到一次
真实事故或一条真实契约——写不出「它防的是哪一次事故」的检查器就该删掉。L3 日常只投到
有嫌疑的面上（由 L0 对账表的 suspect 密度决定），全仓语义体检是季度动作。

## 二、两条元规则

### 规则一：没有执行器的检查不是检查，是收据

每条检查登记在**唯一一份清单**里，每条写明**谁执行它**；清单本身由一条检查守着：
磁盘上的检查器数 == 登记数 + 显式豁免数。三种静默失效：

1. **配了没跑** —— 配置文件里躺着完整配置，全仓零执行器，工具二进制甚至没装。
   **这是最危险的形态：它看起来像装了。** 反复审计多轮也抓不到——审计的眼睛不往配置文件里看。
2. **多份执行器漏改一份** —— 同一份清单被 N 处读取，加门禁只改了一处。
   解法是清单唯一、循环唯一，执行器只负责调用。
3. **只在本机跑** —— 见规则二。

### 规则二：执行器必须至少有一个不在你的机器上

本机钩子可被 `--no-verify` 绕过，且依赖本机环境（venv 在不在、端口占没占、上轮容器收没收）。
**CI 的价值不是「多跑一遍」，是「在一台不是你的机器上、从干净克隆跑」。** 它抓的是本机
永远碰不到的一类：忘记提交的文件、写死的绝对路径、隐式环境变量、依赖上轮残留容器的测试、
lockfile 与实际环境不一致。最小可用版本是 **PR 上跑一次秒级静态门禁**，不必一步到位跑全量。

## 三、缺陷沉降

四层的成本是倒过来的：`L3 ≫ L2 > L1 ≈ L0`，**而缺陷总在最贵的 L3 被发现**。

**每发现一个缺陷，问一句：什么机器能自动抓到这一整类？** 然后往下沉一层——
L3 的假成功沉成 L2 的一条 `check_*`；L2 反复出现的同一形状沉成 L1 的一条 lint 规则；
任何层发现的静默失效各成一页事故页，「防复发」栏要答「哪个门禁守着它、它对旧代码是红的吗」。

沉降的目的是**让 L3 变便宜**。**L3 的复报率是整个体系健康度的核心指标**——
每次都在报同一类，说明这一类没沉下去。

反向有**退役棘轮**：检查只有三种状态——被执行、被显式豁免（带 reason）、被删除。
过期的门禁（里程碑收据、上游已修的补丁校验）必须退役，否则清单变噪音，人就不看了。
**「先放着」不存在。**
