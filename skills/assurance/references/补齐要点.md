# 执行补齐序列时的三件事 · 棘轮默认形态 · 什么不能进提交钩子

### 执行时必须先做的三件（不做会当场翻车，每条都对应一次实际翻车）

1. **跑任何 `--fix` 之前，先装「应用可导入性」门禁**——逐模块真 `import`，零失败才过。
   自动修复会削掉「只做 re-export」的门面模块，而语法检查与全部文本类门禁都抓不到。
2. **死代码工具排除 vendor 之后，vendor 的依赖会全部显示为「未使用」**——删了会在运行时炸。
   判定：`grep -rln "from '<包名>'" vendor/`，命中即误报，加进忽略表并写明理由。
3. **读 git 索引一律 `ls-files -z`**——默认输出对非 ASCII 路径转义，中文命名的文件会被静默跳过。

### 棘轮是默认形态

存量项目的每一条判据都做成棘轮：**存量冻结、只许变短、变少而没重新生成 baseline 也红**
（不收紧的棘轮不是棘轮）。

- **比对逻辑只写一份**，各检查器只负责回答「当前存量是什么」。写到第三条时如果还在复制粘贴，
  先停下来抽出去——四份实现里早晚有一份忘了「变少也要红」。
- **只有覆盖率需要容差**（`max(5, 1%)`）：测试执行不是确定性的。
  lint / 类型 / 死代码是确定性判据，一律零容差。
- baseline **按「位置 + 类别」聚合，不含行号**——行号随任何编辑漂移，带行号的 baseline 撑不过三次提交。

### 什么不能进提交钩子

覆盖率与变异测试**要跑整套测试**，既非秒级也非免依赖，而且**会继承套件里的每一个 flake**。
一条会被无关负载搞红的门禁，就是在教人 `--no-verify`，连带跳过其余全部。
它们归 CI 或人工，登记在清单的豁免区并写明由谁执行。

### 判据实现有两份时，Step 1 自己就会假红

本 skill 的检查器与 `~/.claude/bin/assurance-check.py` 是**同一份判据的两个副本**
（skill 那份把判例匿名化了，因此不能靠 diff 全等来守）。判例（2026-08-27）：两条修正
（package.json 依赖段剥离、一次性登记放宽到 CONFIGURED_NOT_RUN）只改进了 bin 那份，
skill 这份漏改——同一个仓，SKILL.md 里那条命令读 16/17 报「变异测试配了没跑」，
全局 CLAUDE.md 里那条命令读 17/17。**这正是元规则一的第 2 种静默失效，发生在本工具自己身上。**

**Step 1 的读数与你记忆里的上一轮不符时，先比两份检查器的代码差异**：

```bash
diff <(grep -vE '^\s*#' ~/.claude/bin/assurance-check.py) \
     <(grep -vE '^\s*#' <SKILL_DIR>/scripts/assurance_check.py)
```

只剩措辞差异才算一致。改判据必须两份同步改，只改一份等于给下一轮埋一个假红。

### 需要人拍板的四类（不要替他决定）

| 类 | 为什么机器定不了 |
|---|---|
| **删不删** | 机器只能证明「没有执行器」，不能证明「可以删」 |
| **豁免的 reason** | 判据是「下一个人能不能核对」，机器只能查它存不存在 |
| **CI 平台启用** | 在仓库设置里，不在仓库文件里 |
| **产品性质的取舍** | 收窄签名、砍功能、改契约 |

遇到这四类：**把事实查清、列出选项、停下来问**。不要顺手做掉。
